# Natural Number Game in Verso (prototype)

A static [Verso](https://github.com/leanprover/verso) site that presents the levels of the
[Natural Number Game](https://github.com/leanprover-community/nng4) and lets players solve them
against the unchanged [lean4game](https://github.com/leanprover-community/lean4game) backend.

The texts, levels and hints come from NNG4; Verso renders them as a book (one page per world and
per level) with a world map, and a small browser client talks to the lean4game relay, which runs the
game's Lean server.

## Layout

```
nng4/        submodule: the game (Lean v4.23.0, lean4game GameServer, Mathlib)
lean4game/   submodule: the engine; only the Node relay in relay/ is used
site/        the Verso project (Lean v4.35.0)
  NNGSite.lean           title page with the world map; includes the worlds
  NNGSite/Worlds/        one chapter per world, generated by scripts/gen_worlds.py, then editable
  NNGSite/Level.lean     directives `:::level "World" n` and `:::worldIntro "World"`
  NNGSite/WorldMap.lean  directive `:::worldMap`: layered layout at build time, SVG, links
  NNGSite/I18n.lean      translations with the game's catalogue (off: `language := "en"`)
  NNGSite/level.js       browser client: WebSocket + LSP to the relay, goals, hints, editing help
  NNGSite/worldmap.js    colours the map from the progress in localStorage
  scripts/gen_worlds.py  generates NNGSite/Worlds/*.lean from the game data
deploy/      patch for the relay used on the public demo server
docs/        design notes (docs/genre.md: a Verso genre for Lean games)
tests/       protocol and end-to-end tests
```

## Running locally

```bash
git clone --recursive <this repo>

# 1. Build the game (writes nng4/.lake/gamedata, which the site reads)
cd nng4 && lake exe cache get && lake build && cd ..

# 2. Start the relay on port 8080 (development mode serves local games)
cd lean4game && npm install && npm run start:relay

# 3. Build the site and serve it on port 8000
cd site && lake build && lake exe nng-site
cd _out/html-multi && python3 -m http.server 8000
```

Open http://localhost:8000. Without further configuration the page connects to
`ws://<host>:8080/websocket/g/local/nng4`.

To render the site for another relay, set `NNG_RELAY_URL` when rendering; a path refers to the
page's own host (`ws://` or `wss://` as appropriate):

```bash
NNG_RELAY_URL=/websocket/g/verso/nng4 lake exe nng-site --output _deploy
```

## How it works

* At build time `:::level` reads `level__<World>__<n>.json` from the game data, converts the
  Markdown texts to Verso blocks and emits the editor and a palette of the available tactics and
  theorems. Levels and worlds record their page during traversal, so the world map can link to
  them.
* In the browser, `level.js` sends `textDocument/didOpen` with URI `file:///<World>/<n>.lean` and
  the proof as text. The relay prepends `import <level module>` and the `Runner` command and starts
  the game's Lean server. Changes must be sent as range edits, since the relay only rewrites
  `didOpen` and shifts line numbers.
* Feedback comes from the RPC method `Game.getProofState` (goals after each line, hints,
  diagnostics, `completed`). Progress (code, solved) is stored in `localStorage`.

## Help for beginners

* Clicking a tactic inserts a template (`rw [|]`, `induction | with d hd`, …) with the right
  indentation. Clicking a theorem or a hypothesis in the goal inserts it where a name is expected;
  on a new line it becomes `rw [h]`, `apply h` or `exact h` depending on its statement, and a
  natural number `n` becomes `induction n with d hd`.
* `·` lines are created automatically: when a tactic splits the goal into cases, and when a case is
  solved. Buttons insert `←`, `·`, `at` and a new line; Undo reverts any change; brackets close
  themselves.
* The goal after the cursor line is shown with the parts changed by that line highlighted.
* Common Lean errors are explained in plain language; the original message is one click away.
* Unknown names in `rw [...]`, `exact`, `apply` are reported by the client, because this version of
  the game server does not report them.

## Public demo server

The demo runs on a separate machine as an unprivileged user:

* `lean4game` in production mode (`npm run build:relay`, then
  `NODE_ENV=production PORT=8080 node relay/dist/src/index.js`), which runs each Lean session in a
  bubblewrap sandbox. The game lives in `lean4game/games/verso/nng4`; the owner `verso` avoids the
  relay's preloaded process queue for `leanprover-community/nng4`.
* The rendered site (`_deploy/html-multi`) goes to `lean4game/client/dist`, which the relay serves,
  so page and WebSocket share one origin.
* `deploy/lean4game-relay.patch`: puts the game's Lean first in the sandbox's `PATH` (Ubuntu's
  `/usr/bin/lake` is an elan shim that fails in the sandbox) and disables the `/import` routes.
* Reachable from outside via a Cloudflare quick tunnel: `cloudflared tunnel --url http://localhost:8080`.
* Each player session needs about 1.7 GB of RAM.

## Tests

```bash
# Protocol: open a level and print the proof state (relay must be running)
RELAY=ws://localhost:8080/websocket/g/local/nng4 node tests/proof-state.mjs Addition 1 proof.lean

# End to end: solve zero_add by clicks in headless Chrome
cd tests/e2e && npm install && BASE=http://localhost:8000/ node clicks.mjs
```
